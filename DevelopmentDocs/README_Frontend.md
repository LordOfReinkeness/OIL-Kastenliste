# Kastenliste OIL — Frontend Design Documentation

## Tech Stack

- React + TypeScript, scaffolded with Vite
- Styling: CSS custom properties (see styling-guide.md)
- Routing: React Router v6
- State: React context for session user (RZ ID, name), no external state library needed
- Mobile-first for user-facing pages, desktop for admin

---

## Routes

| Path              | Page                 | Auth         |
|-------------------|----------------------|--------------|
| `/`               | Home                 | —            |
| `/meeting/:token` | Meeting check-in     | —            |
| `/admin`          | Admin — Overview tab | Admin cookie |
| `/admin/meetings` | Admin — Meetings tab | Admin cookie |
| `/admin/users`    | Admin — Users tab    | Admin cookie |

The admin area feels like a single page — `/admin`, `/admin/meetings`, and `/admin/users` all render inside the same `AdminLayout` with a shared `TabBar` and top bar. Navigating between tabs only swaps the tab content, nothing else re-mounts. Direct URL access to `/admin/meetings` or `/admin/users` is supported and lands on the correct tab.

If the admin cookie is not set on any `/admin*` route, `AdminLoginPopup` is shown immediately before any content renders.

---

## API Client

The API client is **autogenerated** from the project's `openapi.yml` spec using `openapi-typescript-codegen` (or equivalent tool). The generated client lives in `src/api/generated/` and is never edited manually. All API calls in the app go through this generated client. Regenerate by running the codegen script whenever `openapi.yml` changes.

---

## Session State

- On any **user-facing page** (`/`, `/meeting/:token`), if no user is stored in session, `RzIdPopup` is shown on load
- Admin pages do not show `RzIdPopup`
- After identification or creation, `{ id, rzId, firstName, lastName }` is stored in `sessionStorage`
- On page reload session is cleared — user must re-enter RZ ID
- Session state is provided via a `UserSessionContext` accessible throughout the app

## Popup System

### Base: `Popup`

All popups share a common base component responsible for:

- Semi-transparent dark backdrop
- Centered white panel, max-width `480px` on mobile, `560px` on desktop
- Sharp corners (no border radius)
- Close button (top right) — `×`, only shown when closable
- Smooth height transition for expanding popups
- Keyboard: `Escape` closes if closable

Props: `title`, `closable`, `children`

### Popup Variants

**`RzIdPopup`** (not closable)
- Step 1: Single RZ ID input + "Weiter" button
- If user not found: panel expands smoothly to reveal `firstName` and `lastName` fields + "Registrieren" button
- If user already checked in to this meeting: shows info message
- On success: stores user in session, closes popup

**`AdminLoginPopup`** (not closable)
- Single password input + "Anmelden" button
- On failure: inline error message below input
- On success: cookie is set, popup closes, admin page renders

**`WrongAnswerPopup`** (closable)
- Shows "Falsche Antwort" message
- Displays remaining attempts: "Noch X Versuche"
- "Nochmal versuchen" button closes popup and re-focuses answer field

**`NewMeetingPopup`** (closable)
- Shown after successful meeting creation
- Displays the generated meeting link prominently
- Copy-to-clipboard button next to the link
- "Schließen" button

**`EditMeetingPopup`** (closable)
- Full meeting edit form (date, question, answer, question_required, check_answer, max_retries, excuse_deadline_minutes)
- "Speichern" primary button, "Abbrechen" secondary

**`EditUserPopup`** (closable)
- User edit form (rzId, firstName, lastName)
- "Speichern" primary button, "Abbrechen" secondary

**`TokenEntryPopup`** (closable)
- Single meeting token input
- "Zum Meeting" button navigates to `/meeting/:token`
- Triggered by "Einchecken" button on home page

## Pages

### Home Page (`/`)

- `RzIdPopup` shown on load if no session user
- Once identified: greeting line "Hallo, {firstName}"
- Two large equal-width buttons stacked vertically on mobile, side by side on desktop:

```
┌─────────────────────┐  ┌─────────────────────┐
│                     │  │                     │
│   Entschuldigung    │  │    Einchecken       │
│    einreichen       │  │                     │
│                     │  │                     │
└─────────────────────┘  └─────────────────────┘
```

- "Entschuldigung einreichen": calls `GET /api/meetings/next`, then `POST /api/meetings/next/excuse`. Shows inline success or error message (no popup needed here).
- "Einchecken": opens `TokenEntryPopup`

---

### Meeting Check-in Page (`/meeting/:token`)

- `RzIdPopup` shown on load if no session user
- Fetches meeting info from `GET /api/meetings/:token` on mount
- If meeting not found: full-page error message
- Form:
    - Meeting date displayed at top (read-only)
    - Attendance type toggle: two buttons "Vor Ort" / "Online" (acts like a segmented control)
    - Answer field: shown only if `hasQuestion === true`, label shows the question text, required if `questionRequired === true`
    - Submit button: "Einchecken"
- On wrong answer: `WrongAnswerPopup` shown with remaining attempts
- On success: full-page confirmation message "Erfolgreich eingecheckt" with attendance type and optionally answer result

---

### Admin Layout

- Shown for all `/admin*` routes
- `AdminLoginPopup` shown on mount if no admin cookie
- Top bar: "Beer Tracker Admin" title, logout button (right)
- `TabBar` below top bar with three tabs:
    - "Übersicht" → `/admin`
    - "Meetings" → `/admin/meetings`
    - "Benutzer" → `/admin/users`
- Active tab indicated by `2px solid #000000` underline

---

### Admin — Overview Tab (`/admin`)

- "Neues Meeting erstellen" button top right → opens `NewMeetingPopup` (which first shows a create form, then on success switches to showing the link)
- Attendance matrix table:
    - Rows: users (firstName + lastName + rzId)
    - Columns: meetings (date, short format)
    - Cells: `StatusBadge` (present / absent / excused / —)
    - Fixed left column for user names, horizontally scrollable on smaller screens
    - Last column: beer score (count of absent without excuse)
- Export CSV button top right, next to create button

---

### Admin — Meetings Tab (`/admin/meetings`)

- List of all meetings, most recent first
- Each `MeetingListItem` shows:
    - Date and time
    - Question indicator (icon if question is set, greyed out if not)
    - Attendance summary: "12 anwesend · 3 entschuldigt · 2 fehlend"
    - Edit button (opens `EditMeetingPopup`)
    - Delete button (quick delete with inline confirm: button turns red + "Sicher?" on first click)

---

### Admin — Users Tab (`/admin/users`)

- List of all users, alphabetical by last name
- Each `UserListItem` shows:
    - Full name + RZ ID
    - Quick stats: "15 Meetings · 2 fehlend · 1 entschuldigt · 🍺 2"
    - Edit button (opens `EditUserPopup`)
    - Delete button (same two-click confirm pattern as meetings)

## Shared Components

### `Popup` (base)
See popup system above.

### `List`
Wrapper with consistent spacing and a top border. Accepts `children` of `ListItem`.

### `ListItem` (base)
Full-width row with:
- Left: main content slot
- Right: action buttons slot
  Shared by `MeetingListItem` and `UserListItem`.

### `TabBar`
Horizontal tab row with active underline. Navigates via React Router `<Link>`.

### `StatusBadge`
Compact inline indicator.

| Status    | Style                                     |
|-----------|-------------------------------------------|
| `present` | Teal background `#009B91`, white text     |
| `absent`  | Black background, white text              |
| `excused` | Ice blue background `#D9E5EC`, black text |
| `—`       | Empty / no row yet                        |

### `Button`
Three variants: `primary`, `secondary`, `destructive`. See styling-guide.md.

### `InputField`
Label above, input below. Error message slot beneath input. See styling-guide.md.

### `SegmentedControl`
Two-option toggle (used for attendance type). Both options are equal width buttons side by side. Selected option: black background, white text. Unselected: white background, black border.

### `TopBar`
Used on admin pages. Black bottom border, height `64px`, title left, actions right.

## Responsive Behaviour

| Component    | Mobile                                | Desktop                   |
|--------------|---------------------------------------|---------------------------|
| Home buttons | Stacked vertically, full width        | Side by side, equal width |
| Popups       | Full screen width minus `32px` margin | Max `480–560px` centered  |
| Admin tabs   | —                                     | Horizontal tab bar        |
| Admin table  | Horizontally scrollable               | Full width                |
| Admin lists  | —                                     | Full width                |

The admin area does not need a mobile layout. If accessed on mobile it should still be usable but no special mobile treatment is required.
